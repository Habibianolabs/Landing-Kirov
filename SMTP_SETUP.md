# Настройка SMTP для заявок G10 Киров

Дата актуализации: 26 августа 2026 года.

## Схема

```text
Форма на g10.kirov.restoved.ru
  → POST /api/submit-application.php
  → защищённый SMTP Яндекс 360
  → event@restoranoff.ru
  → четыре адреса заказчика + временный Gmail для проверки
```

[FACT] PHP `mail()` больше не используется в новой версии из GitHub. Отправка выполняется библиотекой PHPMailer 6.10.0 через `smtp.yandex.ru:465` с SSL/TLS и авторизацией.

## Что должен сделать системный администратор

1. Владелец ящика `event@restoranoff.ru` создаёт отдельный пароль приложения для Почты Яндекс 360. Обычный пароль от аккаунта не нужен.
2. Системный администратор сохраняет пароль только в закрытой переменной окружения PHP:

```text
G10_SMTP_PASSWORD=<пароль приложения>
```

3. При необходимости явно задаёт остальные параметры:

```text
G10_SMTP_HOST=smtp.yandex.ru
G10_SMTP_PORT=465
G10_SMTP_USERNAME=event@restoranoff.ru
G10_SMTP_ENCRYPTION=smtps
G10_SMTP_AUTH=1
```

4. Загружает из GitHub вместе:

- `api/submit-application.php`;
- `api/lib/phpmailer/LICENSE`;
- `api/lib/phpmailer/src/Exception.php`;
- `api/lib/phpmailer/src/PHPMailer.php`;
- `api/lib/phpmailer/src/SMTP.php`.

5. Проверяет, что PHP имеет расширение OpenSSL и серверу разрешены исходящие соединения к `smtp.yandex.ru` на порт `465`.
6. Отправляет одну тестовую заявку и проверяет ответ endpoint, Gmail и четыре корпоративных ящика.

Пароль приложения нельзя записывать в PHP, HTML, JavaScript, `.env` внутри публичной папки, Markdown или GitHub. В журнале ошибок также нельзя включать полный SMTP-диалог, потому что он может содержать служебные сведения.

## Ожидаемые ответы

- SMTP принял все пять писем: `200` и `{"ok":true}`.
- Нет пароля, не прошла авторизация, недоступен SMTP или отклонён хотя бы один получатель: `503` и понятное сообщение об ошибке на форме.

Production нельзя считать готовым, пока сисадмин не установил пароль приложения, не загрузил весь каталог PHPMailer и реальная заявка не появилась в Gmail и целевых ящиках.
