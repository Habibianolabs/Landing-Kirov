# Система заявок G10 Киров

Дата актуализации: 28 августа 2026 года.

## Production-архитектура

[FACT] Этот раздел описывает предыдущую Telegram-реализацию и временно не используется. С 28 августа frontend открывает Google Форму `https://forms.gle/g696GpGUuFctGQio7` в новой вкладке; ответы записываются в связанную Google Таблицу без обращения к серверному обработчику.

## Предыдущая серверная архитектура

```text
Форма на g10.kirov.restoved.ru
  → POST /api/submit-application.php
  → Telegram Bot API
  → закрытая группа заказчика «Заявки G10.КИРОВ»
```

[FACT] Почтовая отправка отключена. Рабочий PHP-обработчик отправляет заявку только в Telegram. Успех формы возвращается только после ответа Telegram с `ok: true`; при отсутствии настроек, сетевой ошибке или отказе Telegram форма получает `503` и показывает пользователю сообщение об ошибке.

[FACT] В Telegram передаются имя и фамилия, телефон, e-mail, выбранный тариф и источник формы. Сохраняются прежние проверки полей, согласия, скрытого поля-ловушки, времени заполнения, частоты запросов и повторных заявок.

[FACT] Код не содержит значения токена и идентификатора группы. Он читает их из закрытых настроек сервера:

```text
G10_TELEGRAM_BOT_TOKEN=<токен бота>
G10_TELEGRAM_CHAT_ID=<идентификатор группы со знаком минус>
```

Подробная инструкция для системного администратора: [`TELEGRAM_SETUP.md`](TELEGRAM_SETUP.md).

## Что должен сделать системный администратор

1. Взять подтверждённую версию `api/submit-application.php` из GitHub `main`.
2. Загрузить файл на сервер заказчика вместо прежнего обработчика.
3. Сохранить две закрытые серверные настройки `G10_TELEGRAM_BOT_TOKEN` и `G10_TELEGRAM_CHAT_ID`.
4. Убедиться, что PHP может выполнять исходящие HTTPS-запросы к `api.telegram.org`; предпочтительный модуль — cURL, предусмотрен запасной защищённый POST-запрос средствами PHP.
5. Не загружать `.git`, `.env*`, `tools`, Markdown-документацию и `webstat`.
6. После публикации отправить одну тестовую заявку через форму на публичном сайте.

## Проверка

```text
npm run test:backend
```

Автоматическая проверка подтверждает Telegram-only архитектуру, отсутствие почтового кода и отсутствие токена в PHP.

Критерий production-готовности:

1. `OPTIONS /api/submit-application.php` возвращает `204`.
2. Некорректная заявка возвращает `400`.
3. Корректная заявка возвращает `200` и `{"ok":true}`.
4. В группе «Заявки G10.КИРОВ» появляется сообщение с данными тестовой заявки.
5. В серверном журнале есть запись `Telegram delivery accepted` с идентификатором сообщения.
