# Система заявок G10 Киров

Дата актуализации: 26 августа 2026 года.

## Production-архитектура

```text
Форма на g10.kirov.restoved.ru
  → POST /api/submit-application.php
  → защищённый SMTP Яндекс 360
  → четыре адреса заказчика
```

[FACT] Vercel, Resend и PHP `mail()` не используются. Новая версия отправляет письма через авторизованный SMTP Яндекс 360 от имени `event@restoranoff.ru`. Пароль приложения хранится только в закрытых настройках сервера и не попадает в GitHub.

Получатели находятся только в серверном PHP-файле:

- `lp@restoranoff.ru`;
- `rv@restoranoff.ru`;
- `event@restoranoff.ru`;
- `p.spiridonova@restoranoff.ru`.

До первой успешной production-проверки временно добавлен пятый получатель: `nikitaodintsov6@gmail.com`.

Отправитель: `event@restoranoff.ru`. Ответ на письмо направляется на e-mail заявителя через заголовок `Reply-To`.

## Что делает заказчик

Владелец `event@restoranoff.ru` один раз создаёт отдельный пароль приложения Яндекс 360 и передаёт его системному администратору безопасным способом, не через GitHub и не в этот чат.

## Что делает системный администратор

1. Берёт подтверждённую ветку GitHub `main`.
2. Загружает `index.html`, `styles.css`, `script.js`, папку `assets` и `api/submit-application.php`.
3. Вместе с обработчиком загружает каталог `api/lib/phpmailer`.
4. Сохраняет `G10_SMTP_PASSWORD` как закрытую переменную окружения PHP; пароль в файлы проекта не записывает.
5. Проверяет доступ сервера к `smtp.yandex.ru:465` и наличие OpenSSL в PHP.
6. Не загружает `.git`, `.env*`, `tools`, Markdown-документацию и служебную папку `webstat`.
7. После публикации сообщает, что можно провести одну контрольную заявку. Подробности — в [`SMTP_SETUP.md`](SMTP_SETUP.md).

## Проверка без сервера заказчика

```text
npm run test:backend
```

Автоматическая проверка подтверждает, что production PHP использует SMTP, содержит четыре адреса заказчика и временный Gmail, правильного отправителя и `Reply-To` заявителя. Локально реальное письмо не отправляется.

GitHub также запускает сам `api/submit-application.php` с тестовым SMTP-сервером и проверяет, что обработчик возвращает `200`, создаёт ровно пять отдельных писем и правильно заполняет адресата, отправителя, `Reply-To` и данные заявки.

[FACT] Без пароля приложения этим способом проверяется весь наш код и SMTP-протокол до реальной авторизации в Яндексе. Попадание писем в настоящие ящики подтверждается только после настройки сервера и одной production-заявки.

## Критерий production-готовности

1. `OPTIONS /api/submit-application.php` возвращает `204`.
2. Некорректная заявка возвращает `400` и понятное сообщение.
3. Контрольная корректная заявка возвращает `200` и `{"ok":true}`.
4. Временный Gmail и все четыре получателя подтверждают письмо во входящих или спаме.

Ответ `200` означает, что SMTP Яндекса принял все пять писем. Получение в ящиках всё равно подтверждается отдельно.
