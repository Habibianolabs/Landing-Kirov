# Система заявок G10 Киров

Дата актуализации: 26 августа 2026 года.

## Production-архитектура

```text
Форма на g10.kirov.restoved.ru
  → POST /api/submit-application.php
  → встроенная почтовая система сервера PHP mail()
  → четыре адреса заказчика
```

[FACT] Vercel, Resend, Node.js, внешние почтовые сервисы, API-ключи и почтовые пароли в production не используются.

Получатели находятся только в серверном PHP-файле:

- `lp@restoranoff.ru`;
- `rv@restoranoff.ru`;
- `event@restoranoff.ru`;
- `p.spiridonova@restoranoff.ru`.

Отправитель: `event@restoranoff.ru`. Ответ на письмо направляется на e-mail заявителя через заголовок `Reply-To`.

## Что делает заказчик

Никаких дополнительных действий. Не нужно создавать аккаунт, входить в сервис, передавать пароль или добавлять администратора.

## Что делает системный администратор

1. Берёт подтверждённую ветку GitHub `main`.
2. Загружает `index.html`, `styles.css`, `script.js`, папку `assets` и `api/submit-application.php`.
3. Не загружает `.git`, `.env*`, `tools`, Markdown-документацию и служебную папку `webstat`.
4. Проверяет, что PHP исполняет `api/submit-application.php`, а встроенная функция `mail()` разрешена.
5. После публикации сообщает, что можно провести одну контрольную заявку.

## Локальная проверка

```text
npm run test:local-backend
```

Автоматическая проверка подтверждает загрузку frontend, отказ некорректной заявке, защиту локальных секретов и точный состав письма. Дополнительный локальный тест через личный Resend-аккаунт 26 августа вернул `200 OK`; пользователь подтвердил письмо в Gmail. Resend использовался только как временный инструмент разработчика и не входит в production.

[FACT] Локальная проверка не может подтвердить почтовую систему сервера заказчика. После единственной загрузки нужен один финальный production-тест.

## Критерий production-готовности

1. `OPTIONS /api/submit-application.php` возвращает `204`.
2. Некорректная заявка возвращает `400` и понятное сообщение.
3. Контрольная корректная заявка возвращает `200` и `{"ok":true}`.
4. Все четыре получателя подтверждают письмо во входящих или спаме.

Ответ `200` означает, что PHP передал все четыре письма почтовой системе сервера. Он не гарантирует появление письма в ящиках; получение подтверждается отдельно.
