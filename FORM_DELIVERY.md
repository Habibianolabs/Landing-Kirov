# Система заявок G10 Киров

Дата актуализации: 26 августа 2026 года.

## Архитектура

```text
Форма в браузере
  → POST /api/submit-application.php
  → проверка и защита от спама на сервере заказчика
  → HTTPS API Resend
  → адреса из APPLICATION_RECIPIENTS
```

[FACT] Vercel, Vercel Functions и Node.js в этой цепочке не используются. Репозиторий содержит статический frontend и один PHP-обработчик. Секретный ключ Resend и фактические получатели не хранятся в GitHub.

## Настройки сервера

Системный администратор должен задать переменные окружения PHP:

```text
APPLICATION_ENV=production
APPLICATION_RECIPIENTS=<получатели через запятую>
RESEND_API_KEY=<секретный production-ключ Resend>
RESEND_FROM_EMAIL=G10 Kirov <forms@подтвержденный-домен>
APPLICATION_ALLOWED_ORIGINS=https://g10.kirov.restoved.ru,https://www.g10.kirov.restoved.ru
```

Требования к серверу:

- PHP 7.3 или новее;
- расширение cURL либо разрешённые исходящие HTTPS-запросы через `allow_url_fopen`;
- исходящий доступ к `https://api.resend.com`;
- доступ PHP к системной временной папке для ограничения частоты заявок.

## Безопасность

- ключ Resend создаётся с правом только на отправку писем;
- production-ключ должен принадлежать заказчику и по возможности быть ограничен подтверждённым доменом;
- ключ не добавляется в HTML, JavaScript, Markdown, GitHub, архив сайта или адрес страницы;
- `.env*` игнорируются Git;
- тестовый и production-ключи не должны совпадать;
- при смене тестовой почты меняется только `APPLICATION_RECIPIENTS` на сервере, код не изменяется.

## Временная проверка

До подтверждения домена разрешена тестовая схема:

```text
APPLICATION_ENV=testing
APPLICATION_RECIPIENTS=<почта проверяющего>
RESEND_FROM_EMAIL=G10 Kirov Test <onboarding@resend.dev>
```

Тестовый адрес `onboarding@resend.dev` может отправлять письмо только на адрес владельца аккаунта Resend. Это подходит для временной проверки, но не для заявок заказчика.

## Критерий готовности

Система считается рабочей только после всех проверок:

1. `OPTIONS /api/submit-application.php` возвращает `204`.
2. Некорректная заявка возвращает `400` и понятное сообщение.
3. Контрольная корректная заявка возвращает `200` и `{"ok":true}`.
4. Письмо с точной контрольной темой найдено во входящих или спаме получателя.
5. Перед production-пуском получатель заменён на утверждённый список заказчика, а отправляющий домен подтверждён в Resend.

Ответ `200` подтверждает принятие заявки обработчиком. Фактическая доставка подтверждается отдельно по почтовому ящику и журналу Resend.
