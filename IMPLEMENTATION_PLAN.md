## 1. Цель

Создать современный адаптивный лендинг мероприятия «G10. Рестораторы и опердиры России. Перезагрузка» в Кирове, сохранив функциональную полноту лендинга Екатеринбурга, но используя дизайн утвержденного эскиза и палитру готового баннера.

[FACT] Этот документ первоначально описывал план до начала кодирования; актуальное состояние и незакрытые задачи ведутся в `CURRENT_TASK.md`.

[FACT] Техническая основа статическая: семантический HTML, CSS и vanilla JavaScript. React, Next.js, Vite и сборщик не используются; серверная часть — Vercel Function.

## 2. Исходное состояние репозитория

[FACT] В корне находится статический frontend-лендинг G10 Киров: `index.html`, `styles.css`, `script.js`, `assets/site/kirov`, `vercel.json`.

[FACT] Ветка — `main`; в рабочем дереве есть незакоммиченные `index.html` и `styles.css`, а документация обновляется текущей задачей. Первый baseline commit ещё не создан.

[INFERENCE] Существующий код можно использовать как технический ориентир для семантики, модальных окон и доступных аккордеонов, но публичный контент, айдентика, партнеры, портреты и изображения должны соответствовать Кировскому брифу.

### Обязательное действие до разработки

1. Зафиксировать актуальное состояние Кирова и проверить источники.
2. Считать Киров единственным публичным маршрутом и корнем проекта.
3. Создать отдельную ветку с префиксом `codex/`, если пользователь подтвердит работу в этом репозитории.
4. Удалять только проверенные устаревшие или дублирующиеся assets после аудита ссылок и изображений.

## 3. Архитектурные принципы

- Один источник данных для повторяющихся сущностей: партнеры, рестораторы, темы, тарифы, отзывы и получатели формы.
- Один экземпляр модального окна заявки для всех CTA.
- Один универсальный механизм disclosure для программы и partner details; темы сейчас статично раскрыты.
- Один универсальный доступный dialog-controller для заявки, партнеров и lightbox.
- Контент остается читаемым без JavaScript; JavaScript добавляет раскрытие, модальные окна и аналитику.
- Баннер — атомарный asset. На него не накладываются DOM-элементы.
- Все внешние изображения и видео получают локальную/контролируемую стратегию хранения; production не зависит от Tilda CDN для статичных изображений.
- Аналитика и маркетинговые виджеты загружаются только после соответствующего cookie consent.

## 3.1. Что берем из лендинга Екатеринбурга

[FACT] В референсе проверены следующие рабочие паттерны:

- desktop-header: пять якорей и отдельный CTA;
- mobile-header: burger, вертикальное белое меню и отдельный CTA;
- последовательность: hero → партнерские подписи → содержание программы → о проекте → партнеры → программа → CTA → рестораторы → темы → CTA → стоимость → состав стоимости → медиа → отзывы → форма → footer;
- партнерские карточки с кнопкой «Подробнее» и dialog с длинным описанием;
- темы как четыре статично раскрытые группы; все пункты видны без клика;
- программа референса сейчас показывает placeholder «Скоро будет добавлена»;
- два тарифа, четыре пункта состава цены;
- три zoomable event-фото и широкое Rutube-видео;
- пять текстовых отзывов и один видеоотзыв;
- встроенная форма и отдельная форма в modal;
- cookie banner с Accept/Reject/Settings и четырьмя категориями;
- responsive viewport 393 px без горизонтального overflow.

**Не копируем:**

- цвета, типографику, декоративные изображения и композицию Екатеринбурга;
- Tilda zero-block geometry и абсолютное позиционирование;
- предварительно отмеченное согласие формы;
- необязательные поля без `required`/серверной проверки;
- hotlink статичных Tilda assets;
- mobile-конфликт, при котором чат перекрывает hero и открытое меню;
- скрытые popup-заготовки, у которых нет работающих triggers.

**Что делается:**

### Этап 2. Подготовка production-assets

**Что делается:**

1. Открыть PSD в Photoshop или совместимом приложении, которое корректно поддерживает слои.
2. Экспортировать единый PNG 1920×1080 без редактирования.
3. Сравнить экспорт с утвержденным эскизом и контрольным изображением: текст, положение элементов, цвета, края.
4. Не применять crop, retouch, overlays, новый текст, смену шрифтов или цветокоррекцию.
5. Выбрать реальные фотографии партнеров и локаций с участием заказчика.
6. Создать web-derivatives фотографий: корректная ориентация, безопасный crop, responsive размеры, WebP/AVIF только для фотографий.
7. Не конвертировать баннер в lossy-формат без отдельного разрешения.
8. Добавить `alt`-описания и реестр авторских/лицензионных источников.

**Компоненты:** asset manifest.

**Данные:** PSD, 37 JPEG, четыре event-изображения референса, портреты/логотипы после получения.

**Результат:** полный набор оптимизированных production-assets без изменения баннера.

### Этап 3. Design tokens и фон

**Статус на 6 августа 2026:** реализованы светлая blue/white палитра, статичный голубой фон с малоконтрастным pattern и blue-glass surfaces на основных секциях. В карточках партнёров программы поверхности логотипов настроены отдельно для каждой компании.

**Что делается:**

- извлечь palette samples из корректного баннера;
- определить CSS-токены: фон, поверхности, текст, muted text, primary blue, dark blue, border, success/error, shadows, radii, spacing, typography;
- построить светлый голубой фон без резких пятен;
- создать едва заметный диагональный pattern;
- проверить контраст текста на всех поверхностях;
- ограничить декоративный pattern по opacity и density.

**Компоненты:** `PageBackground`, design tokens.

**Данные:** баннер, эскиз.

**Результат:** визуальная база, которая поддерживает баннер, но не копирует Екатеринбург.

## 8. Критерии готовности

Лендинг готов, если одновременно выполнены условия:

- каждый публичный текст имеет подтвержденный источник;
- отсутствующие материалы не заменены выдуманными;
- баннер визуально идентичен утвержденному исходнику;
- дизайн следует эскизу и баннеру, но не копирует Екатеринбург;
- все CTA ведут к работающей форме;
- заявка доставляется на четыре адреса;
- программа не содержит `???`, внутренних комментариев или альтернативных вариантов;
- mobile 320–393 px не имеет горизонтального overflow;
- интерактивность работает клавиатурой;
- consent реально блокирует необязательные скрипты;
- chat widget не перекрывает системные элементы;
- production проходит функциональную, визуальную, accessibility и performance приемку.
